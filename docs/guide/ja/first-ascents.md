# 初登

**初登**カードは、あなたが初登（**FA**）または初フリー登頂（**FFA**）を行ったルートやボルダーの数をカウントします。ルート履歴がキャッシュされている場合、あなたが**ルートセッター**（ボルト打ち／セッティング）としてクレジットされているルートの数も表示されます。

## 必要な準備

- **オーナーログイン** — `APP_PASSWORD`が設定されている場合は、設定を開いてログブックで**FAとマーク** / **FFA**を使用できるようにサインインしてください。訪問者は、少なくとも一つのルートがマークされるとカードやバッジを閲覧できるようになりますが、自分でマークを追加することはできません。
- **オプションのルートデータインポート** — Crag StatsがtheCragの公開ルート履歴からFAおよびFFAを自動マークするようにしたい場合は、サーバーで`ROUTE_DATA_IMPORT=true`を設定してください（下記参照）。手動マークとインポートはどちらも同じ `first_ascents` テーブルに書き込まれ、いずれも非公開メモには依存しません。
- **プライベートメモは無関係です** — **設定 → プライベートメモを表示**は、あなたの**完登コメント**が`/logbook`（および検索）に表示されるかどうかのみをコントロールします。初登カード、FA/FFAバッジ、マイルストーン、またはルートデータのインポートを制限することはありません。

## 初登のマーク付け

各ボタンを押すと直接保存されます (手動の保存ボタンなし)。 theCragのログブックAPIはルート履歴を返さないため、通常の同期ではそれらを取得できません。自分でマークを付けるか、以下のオプションのインポート機能を有効にすることができます。

### 手動でマークする

1. **ログブック**を開き、該当ルートの記録を見つけます。
2. 行にホバーする（またはTabキーで移動する）と、**FAとマーク**または**FFA**を押します。
3. 元に戻すには**マーク解除**を押します。

設定を開くことができるユーザーのみがFAをマークできます。`APP_PASSWORD`が設定されていない場合は全員、設定されている場合はログイン時のみ可能です。訪問者にはFAバッジとカードが表示されますが、ボタンは表示されません。

マークはtheCragのルートIDに対して保存されるため、再同期後も維持されます。 theCrag上でそのルートのすべての記録が削除されるとカードから消え、再度ルートを記録すると復活します。**設定 → 消去**を実行すると、すべてのマークが削除されます。

### ログブックをフィルタリングする

**ログブック**で**初登マーク**コントロールを使用すると、FA、FFA、その両方、またはまだマークが付いていないクライミング（`?fa=FA|FFA|any|none`）のみを表示できます。ルートデータのインポートが有効になっている場合、オーナーは**履歴未確認**（`?history=pending`）も利用でき、インポーターがまだ取得していないクライミングがリスト表示されます。

### ルート履歴からインポートする（オプション、デフォルトはオフ）

サーバー所有者がこれを有効にすると（`ROUTE_DATA_IMPORT=true`。旧バージョンでは`ROUTE_HISTORY_IMPORT`と呼ばれていましたが現在は読み込まれないため、名前を変更して再起動してください）、Crag StatsはバックグラウンドでtheCragから各ログブックルートの公開履歴を読み込み、あなたを指名しているFAおよびFFAにマークを付けます。

- **theCragユーザー名**（`@yourlogin`）が指定されているエントリーのみがカウントされます。プレーンテキストの名前は同姓同名などの混同が生じやすいため無視されます。 API同期によりそのログイン情報が保存されます。ログブックがCSVアップロードによるものの場合は、インポートがどのエントリーをあなたのものとして識別できる用`THECRAG_USERNAME`を設定してください。
- **手動の設定が優先されます。** 設定したマークはそのまま維持され、マークを解除したルートは解除されたままになります。**設定 → ルートデータをインポート → 再適用**を使用すると、theCragに再度問い合わせることなく、保存済みの履歴を使ってどちらの設定も上書きできます。
- **theCragへの負荷に配慮。** 各ルートはデフォルトで**一度**のみチェックされ (オプションの定期的なデータ更新については下記参照)、一回の実行につき最大**100ルート**、一秒間に一リクエストの制限が適用されます。 A run happens after each logbook sync or CSV upload, on the background import schedule (`IMPORT_CRON`, daily by default), when the app restarts with routes still waiting (for example after an upgrade), or when you press **Check next 100 routes now**. theCragからリクエスト制限、レートリミット等を受けた場合、インポートは少なくとも一日間一時停止します。
- 設定には、これまでにチェックされたルートの数が表示されます。日次同期の場合、数百ルートの処理に数週間かかりますが、ボタンを押すことで処理を高速化できます。

公開ルート履歴のみが保存され、非公開の完登メモが保存されることはありません。**設定 → 消去**を実行すると、マークと一緒に削除されます。

## カードの表示内容

カードにインポートされたFA/FFAまたはセッターのクレジットが含まれている場合、フッターにtheCragルート履歴の出典が表示されます。これは後からインポートが無効化された場合でも、保存されたクレジットに従って表示されます。手動マークには出典ラベルは必要ありません。混在しているコレクションでは、ルート履歴のクレジットが保持されます。

- **数:** 手動マークまたはルートデータインポート（公開ルート履歴）から、FAまたはFFAとしてクレジットされているルートの数。 FFAがある場合は、FA / FFAの内訳も表示されます。
- **開拓・設定したルート:** キャッシュされた履歴であなたがルートセッター（`@yourlogin`）として記録されている個別のルート。 FAインポートと同じ`@login`ルールが適用され、フリーテキストの名前はカウントされません。それらの行をローカルに保存するには、ルートデータのインポート（`ROUTE_DATA_IMPORT=true`）が必要です。
- **コミュニティ完登数 (推定):** あなたが開拓／初登したルート、初登マーク**または**セッタークレジットのキャッシュされた完登 (ティック) 数から、同じ取得時に記録されたあなた自身のログブックの完登数を引いたもの。二つ目のタイルには**スポーツ／ボルト設置**ルート (スポーツのギアスタイル、またはボルトが記録されているルート) が内訳として表示されます。後からオーナーが再登または削除を行っても、過去のスナップショットは変更されません。これらは総完登数の推定値であり、ユニーククライマー数やリアルタイムカウンターではありません。公開設定の違いやオーナーのログブックが不完全であることにより影響を受ける場合があります。
- **コミュニティカバー率:** 対象となる全ルートのうち、カウントスナップショットが対になっているクレジット済みログブックルートの数がカードに表示されます。合計がゼロと判明しているものはゼロとして表示され、取得できないカウントはゼロとして扱うのではなく除外されます。一部のみカバーされている場合は、明確にラベル付けされます。キャッシュが完全に存在しない場合は、利用不可のメッセージが表示されます。
- **年数:** 最初のFAの年から最新のFAの年まで。各FAの日付は、該当ルートの**最初のログ記録された完登**の日付になります (下記参照)。
- **グレード範囲:** ルート全体のグレード（単一ピッチではなく）を使用した、最も易しいFAと最も難しいFA。 EwbankとVグレードは比較できないため、ルートとボルダーは別々に表示されます。グレードは、設定されているルートおよびボルダーの表示システムで表示されます。
- **スタイル:** theCrag上のルートのスタイルを使用した、スポーツ、トラッド、ボルダーなどのFAの内訳。
- **最新:** ダッシュボードカード上の最も新しい三つのFA (全リストはログブックで確認可能)。
- **ルート別コミュニティ:** ダッシュボード上のクレジットされた上位三ルート (リストの下にさらにカウントが表示されます)。
- **ルート別コミュニティ:** コミュニティ推定値順にランク付けされた最大八つのクレジット済みルート。各行には、FA、FFA、および/またはセッターのクレジット、スタイルバッジ（Sport/bolted、Trad、Boulder、またはキャッシュされたルート情報からのその他の既知のギアスタイル）、推定値（または「利用不可」）、およびそのカウントが取得された日時が表示されます。カウントの更新日時は他のルート情報フィールドとは別に保存されるため、ムーブ情報のベータや品質のみを更新しても、カウンターが新しく更新されたようには装いません。

少なくとも一つのFAがマークされるまで、訪問者にカードは表示されません。それまでは、オーナーに代わりの短い使い方が表示されます。

カウントスナップショットを取得するには、ルートデータのインポート（`ROUTE_DATA_IMPORT=true`）が有効になっている必要があります。コミュニティ合計およびオーナーカウントのスナップショットは、バックグラウンドインポート中にルートAPIから取得されます (100ルート/回、ペース制御とバックオフが適用されます)。合計やその他のルートデータを自動的に最新状態に保つには、`ROUTE_DATA_IMPORT=true`と並行して`ROUTE_DATA_REFRESH_DAYS`を30から3650の整数の日数（例: 推奨`90`、または約半年の`180`）に設定します。その日数が経過したルートが対象となり、ログブックの同期が成功した後に更新されます。この処理は新しいルートと100ルート分の枠を共有します。新しいルートが優先され、次に最も古い未更新データが処理されます。未処理データが多い場合は複数の同期を要することがあります。未設定、`0`、30未満、または3650を超える場合は「一度のみ取得」の挙動が維持されます。設定の**すべて更新**は手動リセットのオプションとして利用可能です。手動でのマークおよびマーク解除は保持され、保護されます。

設定では、ルート履歴チェックボタンが次の実行が許可されるまでカウントダウンし、自動的に利用可能になります。実行間隔は最低一分です。ブロックやエラーが発生した場合は、より長い待ち時間が必要になることがあります。 JavaScriptが無効な場合は、設定を再読み込みして利用可能性を更新してください。

## FAがカウントされるタイミングとその日付

初登とは完登を意味するため、それぞれマークされたルートの**最初のログ記録された完登**の日付が付けられます。トライ中の過去のトライやテンションはカウントされず、その後の再登もカウントされません。これまでにトライのみを記録している場合でもルートはカードに表示されますが（最初の記録の日付）、完登を記録するまではバッジやマイルストーンを獲得することはできません。

## バッジとマイルストーン

これらは、プライベートメモの有効化ではなく、オーナーがマークしたFA/FFA（およびマークされた各ルートの最初の完登）によって解除されます。マイルストーンカードとバッジカタログは同じしきい値を使用します、ルートごとに一行ではありません。

- **初登**および**初フリー登頂:** FAまたはFFAとしてマークしたルートの最初の完登。
- **初登合計数**（5、10 / パイオニア、20、50、100）: FAまたはFFAとしてマークされたその数の異なるルート。
- **初フリー登頂数**（5、10、20、50、100）: FFAマークのみ。
- **スタイル別初登数**（Sport、Trad、Boulderで10、20、50）: そのギアスタイルでのFAまたはFFAマーク。
- **ルートセッター**、**ルートデベロッパー**（5）、**ウォールビルダー**（10）、**クラグアーキテクト**（25）: キャッシュされたルート履歴からのルートセッタークレジット。各ルートであなたの`@login`を指名している最も古いセッターエントリーの日付が使用されます（ログブックの完登日ではありません）。
- **シェアード・クラグ**（10）、**クラウドプリーザー**（50）、**ハンドレッドハンズ**（100）、**ローカルクラシック**（500）: 対になったカウントスナップショットからの、あなたが拓いたルート（FA/FFAまたはセッター）の概算コミュニティ完登数。カウントは完登数であり、ユニーククライマー数ではありません。不完全なカバー率はバッジの詳細に記載されます。
- **ボルト・バズ**（10）、**スポーツマグネット**（50）、**クリップクラシック**（100）: スポーツのギアスタイルまたはボルト設置ルートに限定された同じ推定値。

各しきい値の日付は、それを超えたルートの最初の完登日となり、詳細にはその条件を解除したルート名が表示されます。

有効な履歴日付がないセッタークレジットもセッターバッジのカウント対象になりますが、獲得日は不明のままとなります。コミュニティ完登バッジも同様に獲得日は不明のままです。合計値はキャッシュされた集計値であり、特定のイベント日ではないためです。
