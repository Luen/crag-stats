# ログブックの同期

Crag Stats は次の二つの方法のいずれかでログブックを取得します。

- theCrag サポーター API キーによる **API 同期**。既存のスケジュール（`SYNC_CRON`、デフォルトは毎日）、**Settings → Sync now**（**`/settings`** を開く。`APP_PASSWORD` が設定されている場合はまず **`/login`**）、および Docker ワーカーから実行されます。新規インストールでは、キーが設定されている場合、起動時に同期が行われます。
- **手動 CSV アップロード**。更新したいときに theCrag でログブックをエクスポートし、**Settings → CSV import** でファイルをアップロードします。

## バックアップ: ローカルコピーの保持

最新のログブックの信頼できる情報源は、引き続き theCrag アカウントです。 Crag Stats は同期された登攀記録、設定、目標、ルート履歴キャッシュ、天気データ、関連する状態を **SQLite**（`DATABASE_PATH`、通常は Docker 内の `./data/crag-stats.sqlite` または `/data/crag-stats.sqlite`）に保存します。 Docker の **データボリューム**（または `/data` にマウントしたホストディレクトリ）を、他のホームラボのバックアップと一緒にバックアップしてください。整合性のあるファイルバックアップを作成するには、そのデータベースを使用しているすべてのアプリとワーカーを停止し、`-wal` / `-shm` サイドカーファイルを含むボリュームをコピーしてから、再起動してください。書き込みが実行されている間にこれらのファイルを一つずつコピーすると、不整合なバックアップが作成される可能性があります。アプリを実行したままにする必要がある場合は、SQLite に対応したオンラインバックアップツールを使用してください。 Compose はイメージのアップグレード後もボリュームを保持します。

スプレッドシート形式のポータブルなコピーを取得するには、**Settings → Privacy & data control** を開き、**Download logbook CSV** を使用します（`/settings/export` と同じ動作）。このファイルは、ローカルログブックの theCrag 風 CSV ファイルです。ルート、登攀記録、パートナー、星数、日付、コメント/メモが含まれます。バックアップ目的のダウンロードであるため、メモは常に含まれます。このファイルは個人データとして取り扱ってください。後で **Settings → CSV import** で再インポートできます（アップサートのみ。ファイルにない登攀記録は削除されません）。 theCrag から再構築する際のフォールバックを確保したい場合は、**Wipe all local data** を実行する前に CSV をダウンロードしてください。完全な復元経路としてはボリュームバックアップが推奨されます。

Settings の CSV は Crag Stats から出力されるものであり、theCrag から直接取得したものではありません。ログブック自体のアップストリームバックアップとしては、オンラインログブックで theCrag 本体の **Action → Export logbook as CSV** も使用してください。

## 手動同期でインポートされた内容

**Sync now** または **Full re-sync** が成功すると、設定画面に処理された登攀記録、
新規登攀記録、更新された既存の登攀記録、新規ルート、および削除された登攀記録/ルートが表示されます。複数の登攀記録で共有されているルートは、一つの新規ルートとしてカウントされます。 「Refreshed」は、
既存の登攀記録が再処理されたことを意味します。内容が変更されたことを意味するわけではありません。そのため、変更のないログブックでは、追加・削除が ゼロ 件となり、既存の登攀記録が
更新済みとして表示されます。スキップされた実行やエラーは独自のメッセージを表示し、成功サマリーは表示しません。

手動 CSV アップロードでも処理済み/新規/更新済みの件数が表示されますが、ファイルに含まれていないエントリーが削除されることは
ありません。 Route data and weather enrichment are separate background
imports: when enabled, they start after every successful sync or CSV upload
(including uploads to `POST /api/logbook/csv`), and are not included in these
logbook counts. サマリーは完了した
ボタンアクションの内容を示すものであり、永続的な同期履歴ではありません。

## API 同期

`THECRAG_API_KEY` にサポーターログブック読み取りキーを設定します。各同期処理では、ログブック全体を読み込み、削除されたものも含めてローカルの登攀記録との整合性を取ります。このモードでは、より詳細なルート、プロフィール、マルチピッチのデータが提供されます。また、Crag Stats がログブック取得のために theCrag へ自動接続する唯一の方法です。

### API 同期が失敗した場合

Settings に失敗が表示され、最後に成功した同期の日時が保持されます。 theCrag から原因が報告された場合、メッセージに原因と theCrag のショートエラーコード（例: `invalid-api-key`）が表示されます。

- **Invalid key:** theCrag が `THECRAG_API_KEY` を拒否しました。誤字がないか確認するか、有効期限切れや失効している場合は置換して、サーバーを再起動してください。
- **Access denied:** キーにログブックの読み取り権限がありません。サポーターキーを確認するか、代わりに CSV エクスポートを手動でアップロードしてください（下記参照）。
- **Usage limit:** キーが theCrag のリクエスト制限に達しました。リセットされるのを待ってから、再度同期してください。

後続のページでエラーが発生した場合、前のページで取得した更新はキャッシュに残りますが、不足している登攀記録の削除は行われず、実行は成功として記録されません。次回の定期実行（デフォルトは毎日）または **Sync now** により、1ページ目から全ログブックの再試行が行われます。 API エラーが発生してもスケジュールは一時停止されません。

## 手動 CSV アップロード

サポーターキーをお持ちでないですか？ theCrag でログブックを開き、**Action → Export logbook as CSV** を選択して、**Settings → CSV import** でファイルをアップロードします。新しい登攀記録を取り込みたいときにこの操作を繰り返します。

手動アップロードは登攀記録の追加および更新を行いますが、ファイルに含まれていない登攀記録を削除することはありません。削除された登攀記録を破棄するには、**Wipe all local data** を実行してから最新のエクスポートファイルをアップロードしてください。 CSV は API に比べてプロフィール、ルートメタデータ、マルチピッチ情報などのフィールドが少なく、theCrag の非公開登攀メモ（`privateMarkdown`）は含まれません。公開されている Comment 列のみがインポートされます。オーストラリアの数字のみのボルダーグレードは、誤って架空の V グレードに変換されないよう Country / path を AU ヒントとして使用します。

ルートデータのインポートでは、FA/FFA のクレジットをあなたの theCrag ユーザー名と照合します。 API 同期モードではプロフィールからユーザー名が保存されるため `THECRAG_USERNAME` は無視されます。CSV のみのインストールの場合は代わりにこれを設定します。ログイン情報がないと何を取得する前にもインポートが停止するため、設定してください（またはログブックで手動で初登をマークしてください）。

## ルートデータ付き CSV ログブック

ログブックを CSV で管理しながら、ルートデータ（人気度、登攀回数、星数、シーズン性、ピッチ数）や自動 FA/FFA マークを維持することができます。以下を設定します:

- `CSV_INGEST_TOKEN`: 長いランダムな値。これはコンテナやスクリプトから CSV エクスポートを送信できるようにするものであり、アップロードがログブックのソースであることを Crag Stats に伝える役割も果たします。API 同期は実行されないためアップロードされた登攀記録が削除されることはなく、キー所有者のクライマープロフィールが同期によって書き込まれることもありません。
- ネットワークから読み取り可能な場所、共有フォルダ、Nextcloud や Dropbox の共有、新しいエクスポートをアップロードする小型コンテナなどにエクスポートファイルを保存している場合、Crag Stats は代わりに HTTP 経由でそれを受け取ることができます。
- `THECRAG_USERNAME`: あなたの theCrag ユーザー名。FA/FFA 履歴を照合するために使用されます（CSV エクスポートには含まれません）。

設定はこれで以上です。三つの値のみで、モード切り替えはありません。 `CSV_INGEST_TOKEN` が設定されていない場合、`THECRAG_API_KEY` がログブックを同期し、ルートデータも同じキーを共有します。 Background route and weather imports start after each successful sync or CSV upload, and also follow `IMPORT_CRON` (daily by default) rather than the logbook schedule, so a weekly or monthly `SYNC_CRON` still gets route data daily. Settings → **Import route data** で進捗が表示され、手動で実行を開始できます。

## 別のコンテナからの CSV アップロード

たまに更新する程度であれば、手動でのアップロードで問題ありません。ネットワークから読み取り可能な場所、例えば共有フォルダ、Nextcloud や Dropbox の共有、新しいエクスポートをアップロードする小型コンテナなどにエクスポートファイルを保存している場合、Crag Stats は代わりに HTTP 経由でそれを受け取ることができます。 `CSV_INGEST_TOKEN` に長いランダムな値を設定して再起動し、ファイルを `POST` します:

```bash
curl -X POST https://cragstats.example.com/api/logbook/csv \
  -H "Authorization: Bearer $CSV_INGEST_TOKEN" \
  -H "Content-Type: text/csv" \
  --data-binary @thecrag-logbook.csv
```

`file` フィールドにファイルを指定したマルチパートアップロードも可能です。トークンのないリクエストは拒否されます。成功レスポンスには、処理された登攀記録の数と新規登攀記録の数が報告されます:

```json
{ "ok": true, "imported": 412, "created": { "routes": 318, "ascents": 412 } }
```

何もインポートせずにインストール状態を確認するには、エクスポートファイルではないボディを送信します:

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://cragstats.example.com/api/logbook/csv \
  -H "Authorization: Bearer $CSV_INGEST_TOKEN" \
  -H "Content-Type: text/csv" --data-binary 'x'
```

`400` はエンドポイントに到達可能でトークンが受け入れられたことを意味します。ボディが拒否されたため、何も書き込まれていません。 `401` はトークンが一致しなかったことを意味し、`404` はイメージがこのエンドポイントの実装前のものであることを意味します。 UI 全体に認証がかかっているインストール環境（`AUTH_SCOPE=all`）では、古いイメージは不明な `/api/` パスに対して `401` を返すため、`401` は「トークンまたはイメージのエラー」と読み替えてください。

空のファイル、誤って保存されたログインページ、または 25 MB を超えるファイルはインポートされず拒否されます。このエンドポイントは Settings フォームと同じアップサート専用のインポートを行うため、ファイルに含まれていない登攀記録が削除されることはありません。このエンドポイントは theCrag へのリクエストを行いません。エクスポートファイルはユーザー自身のブラウザまたは自身で管理する別のツールから取得する必要があります。

## 自動 CSV ダウンロード機能がない理由

Crag Stats が theCrag Web サイトにサインインしたり、ユーザーに代わってエクスポートをダウンロードしたりすることはありません。 theCrag の [利用規約](https://www.thecrag.com/terms#ownership-and-licenses) では、すべてのプログラムによるアクセスが API を経由することが要求されており、エクスポート処理はサーバーに負荷がかかる全ログブックのダンプ処理となるためです。自身で CSV をエクスポートしてアップロードすることは問題ありません。
