# ルートの人気

**ルートの人気**カードは、theCragが各ルートについてキャッシュしているコミュニティ統計情報: **登攀回数**、**人気**、**相対的人気** (0–100) を使用します。 Crag Statsは、ルートデータのインポート実行時（サーバーで `ROUTE_DATA_IMPORT=true` を設定し、再起動して同期）にこれらを保存します。

## 定番ルート vs 穴場ルート

人気データが存在する各登攀について、可能な場合は**相対的人気**を、そうでない場合は**グローバルな人気**を比較します：

| 分類        | ルール         |
| --------- | ----------- |
| **定番ルート** | スコア ≥ 50    |
| **穴場ルート** | スコア &lt; 50 |

このカードは、**これらの記録の割合**が各分類にどのように配分されているかを示します。キャッシュされた統計データのないルートでの登攀は、パーセンテージから除外されます。

## 隠れた名ルート

**隠れた名ルート**とは、評価が高く（`qualityScore` ≥ 70、または少なくとも ★★★、あるいは自身の記録に質の高いラベルがある）、かつ登る人が少ない（コミュニティの**登攀回数** ≤ 100 かつ人気スコア &lt; 50）ルートでの**完登**を指します。クオリティ順に、最大三つの異なるルートが表示されます。

## ログブック

**人気**でソートすると、ルートの人気順 (デフォルトでは高い順) に記録を並べ替えます。キャッシュされた統計がない行は、一番下にソートされます。

## ソース

数値はtheCragのルートAPI（`show=info`）から取得されます。これらはあなた自身のログブックだけでなく、コミュニティ全体のデータを反映しています。

人気の算出には、利用可能な場合は相対的人気を、そうでない場合はグローバルな人気を使用します。コミュニティの登攀回数は個別に表示され、人気スコアと数値で比較されることはありません。

コミュニティの登攀合計数、人気、評価を最新の状態に保つため、サーバーの所有者は `ROUTE_DATA_IMPORT=true` を有効にした上で、`ROUTE_DATA_REFRESH_DAYS` に30日から3650日までの整数（推奨は `90`、半年程度なら `180` など）を設定できます。これらはローリング日単位の期間です。ログブックの同期が成功した後、新しいルートが優先され、その後、同じ100ルート制限とペースの中で、最も古い期限切れデータが更新されます。バックログの解消には、数回の同期が必要になる場合があります。未設定、`0`、30未満、または3650を超える値の場合は、デフォルトの「一度だけ取得する」キャッシュ設定が維持されます。設定内の**すべて更新**は引き続き利用可能です。
