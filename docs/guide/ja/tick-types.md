# ティックタイプ

**ティックタイプ**は、単に頂上に到達したかどうかだけでなく、_どのように_登ったかを記録するものです。オンサイトは、同じルートのレッドポイントよりも高い価値があります。そのため、theCrag（および Crag Stats）ではこれらを区別して扱っています。

下の表において、**Send** とは Crag Stats がその記録を成功した（クリーンな）登攀としてカウントすることを意味します。例えば「成功した登攀」、完登率、ピラミッドなどで使用されます。 **Attempt** とは試登として記録されることを意味します。チャート上では灰色で表示され、登攀ボリュームとしてカウントされるほか、そのルートをプロジェクトとしてマークできます。

## ここでのティックの使われ方

- **ピラミッドとチャート**では、各ティックタイプを一貫した色で表示します：オンサイトは緑、フラッシュは黄色、レッドポイントは赤、ピンクポイントはピンク、完登/クリーンは青、アテンプトは灰色です。
- **CPR** は、各ティックをグレードのオフセットによってシフトさせます（オンサイトはレッドポイントよりも難易度が高いとみなされます）。詳細は [CPR](/docs/cpr) を参照してください。
- **プロジェクト**とは、アテンプトはあるが、まだ完登していないルートのことです。初回のトライで完登した（オンサイトまたはフラッシュ）ルートがプロジェクトになることはありません。
- ルートのワーキングもハードな活動であるため、**トレーニング負荷**ではアテンプトを完登の0.8倍としてカウントします。詳細は [トレーニング負荷](/docs/training-load) を参照してください。

## 分析対象となるティックタイプ

theCrag では、完登以外の試登（`Working`、`Attempt`、`Hang dog`、`Retreat` など）も登攀として記録されます。プロジェクトの攻略中に多数のワーキングを記録する場合、すべてのトライをダッシュボードの合計に含めると、主要な完登数、スタイル構成比、クライマータイプが歪んでしまう可能性があります。

**設定 → 表示と表示設定 → カウントされるティックタイプ** で、Crag Stats 全体での各ティックタイプの扱いを設定できます：

- **有効（すべてでカウント）:** 主要な完登数、種目別内訳、岩場とセクター、ピラミッド、マップ合計、エディントン数、ルートのリピート、クライマープロフィールの軸、アクティビティヒートマップ、トレーニング負荷、バッジ、プロジェクト、目標に含まれます。
- **プロジェクトと目標のみ（合計から除外）:** 主要な完登数、種目構成比、岩場、セクター、ピラミッド、マップ合計、エディントン数、ルートリピート、クライマープロフィールの軸からは除外されますが、プロジェクトの検出、セッションアクティビティ（ヒートマップ、ストリーク、週ごとのセッション、曜日別チャート）、トレーニング負荷の疲労度、バッジ、グレード目標にはカウントされます。
- **非表示（完全に除外）:** すべての分析、プロジェクト、目標、バッジから除外されます。

ログブックでは、この設定にかかわらず、記録されたすべての登攀が保持され、フルフィルタリング機能で表示されます。どの選択肢がどのバッジに対応するかについては、[バッジ](/docs/badges) を参照してください。

特定のティックタイプをカウントから除外するように設定した場合、ダッシュボードは通常 theCrag から取得されるプロフィールの数値（外岩およびジムの完登数、記録ルート数、合計高度、クライマータイプ）をカウント対象の記録から再計算します。これにより、ページ上のすべての合計値が同じティックのセットを反映するようになります。**すべての記録済みティック** プリセットを選択して設定をクリアすると、theCrag 独自の合計値に戻ります。
