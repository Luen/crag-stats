# 天気

Crag Statsは、ルートの座標がある登攀について**日次の屋外の天気**をキャッシュし、それをバッジ、ダッシュボード、ログブックの表示、および異なる天候下でのクライミングのパフォーマンス比較に使用できます。

## オプトイン

デフォルトではオフです。サーバーの所有者が`.env`内で`WEATHER_IMPORT=true`を設定して再起動します。 After each successful logbook sync or CSV upload, on the background import schedule (`IMPORT_CRON`, daily by default), and from **Settings → Import weather**, Crag Stats fetches up to **50** missing outdoor days per run from [Open-Meteo](https://open-meteo.com/)'s historical weather API, oldest climb days first, with at least **1.1 seconds** between requests. 設定からのアクションはその実行をバックグラウンドで開始するため、ページがバッチ全体の完了を待つことはありません。「ワイプ」を実行するとキャッシュが消去されます。

Open-Meteoの無料の非商用ティアは、個人用のセルフホストインストールを想定しています。規約と有料オプションを確認せずに、商用のマルチテナントサービスでこれを有効にしないでください。

## 取得される内容

- **屋外のみ** — インドアやジムのルートと思われるものはスキップされます（目標と同じヒューリスティックを使用）。
- **座標が必要** — ルートに緯度と経度がある必要があります（theCragの同期、またはCSVログブックのルートデータインポートから取得）。
- **過去の日付** — 本日のUTC日付はスキップされます。当日のアーカイブは不完全であることが多いためです。
- **共有キャッシュキー** — 緯度・経度は**小数点第一位**に丸められるため、近接する岩場のルートは同じ日付の行を共有します。

保存されるフィールド：日次最高/最低気温（°C）、降水量（mm）、WMO天気コード、平均湿度、および最大/平均10m風速（km/h）。気温（°Cまたは°F）、風速（km/hまたはmph）、降水量（mmまたはin）の表示単位は、**設定 → 表示と公開設定**で選択できます。

## バッジ

日付がキャッシュされると、その場所でのその日の**屋外**のログ記録（アテンプトも含まれます。キャッシュされた緯度・経度を共有していても、インドアやジムの行はスキップされます）から、以下のバッジを獲得できるようになります：

| バッジ          | ルール                                               |
| ------------ | ------------------------------------------------- |
| **ヒートウェーブ**  | その日の最高気温 ≥ 35°C                                   |
| **フリーズフレーム** | その日の最低気温 ≤ 0°C                                    |
| **レインチェック**  | 降水量 1 mm以上、かつ雪に分類されない                             |
| **雪中クライミング** | WMO雪コード（71–77、85–86）、または降水量 1 mm以上かつ最高気温 1°C以下    |
| **ブローンアウェイ** | その日の最大10m風速 ≥ 50 km/h                             |
| **ブルーバード**   | 最高気温 15–25°C、測定降水量 0.1 mm未満、かつWMOコードが雪または雷雨でない    |
| **スティッキー**   | 平均湿度 ≥ 85%                                        |
| **ストームセンド**  | 雪以外の降水量が 10 mm 以上の日の**完登**                        |
| **フォーシーズン**  | ヒートウェーブ、フリーズフレーム、レインチェック、雪中クライミングをそれぞれ少なくとも一度獲得する |

`WEATHER_IMPORT`がない場合（またはバックログの取得前）は、それらの条件下で登攀していても、これらのバッジはロックされたままになります。「スコーチャーストリーク」（一週間に多数の酷暑日がある場合）は延期されます。

## 天気の詳細ページ

アナリティクスのサイドバー、またはダッシュボードの天気カードのタイトルのいずれかから[天気](/weather)を開きます。ダッシュボードには、明確な傾向がある場合に、コンパクトなコンディション情報と「最高気温/完登率」のサマリーが表示されます。明確な傾向がない場合、パフォーマンス表示は詳細なバンドとコントロールを保持します。詳細ページでは常にフルビューが表示されます。保存されたダッシュボードカードの表示設定と位置は引き続き適用されます。

詳細ページでは、パフォーマンスのグルーピングと指標がURL（`group=temperature|conditions`、`measure=sendRate|nearLimit|onsightFlash`）に保存されるため、ビューをブックマークしたり「戻る/進む」を使用したりできます。天気のパターンは相関関係を示すものであり、推奨事項や原因を示すものではありません。

**カバレッジと場所の品質**では、キャッシュされた使用可能な場所・日付、天気が取得不可だった確認済みの日の、および（今日や将来の日付を含む）未確認の日を分けて表示します。有効な日付はあるが場所が特定されていない屋外の登攀は、別途カウントされます。これらは特定の場所・日付に割り当てることができないため、分母からは除外されます。コンディションは屋外のすべての記録をカウントし、パフォーマンスは完登とアテンプトのみをカウントします。インポートと場所のコントロールは「設定」に残りますが、ログインしている所有者のために「天気」ページからもリンクされています。

屋外の天気がキャッシュされていない場合、ページにはインポートの仕組みについての説明が表示されます。キャッシュが少ない場合でも、コンディションは表示されますが、パフォーマンスは既存の最小サンプルが揃うまで待機します。「天気」ページを表示するだけでプロバイダーにデータをリクエストすることはありません。

## 天気のコンディション

ダッシュボードの**天気のコンディション**カードは、少なくとも一日分の屋外クライミングの天気データがキャッシュされると表示されます。`WEATHER_IMPORT`がない場合（または最初の取得が完了する前）は非表示のままです。他のカードと同様に、**設定 → ダッシュボード**から表示、非表示、または移動が可能です。

- **日**は「場所・日」を意味します。キャッシュされた一つの場所（緯度・経度は小数点第一位で丸められます）におけるカレンダー上の一日です。二つの岩場にまたがる日は二回としてカウントされます。ジムやその他のインドアと思われるルートはカウントされません。
- **カバレッジ**は、キャッシュされた天気の行がある日と、ルートの座標があるすべての屋外の日を比較します。使用可能なキャッシュ行がない日（未確認の日や、確認したが取得不可だった日を含む）は「使用可能な天気なし」としてリストされ、コンディション表示の他の数値からは除外されます。
- **最も暑い/寒い登攀**には、その日の最高気温と最低気温を使用します。リンク先は、その日にtheCragで最も早くログ記録された登攀になります。
- **日の割合**には、キャッシュされた天気がある日のうち、完璧な日、雨の日、雪の日、氷点下の日、暑い日の割合が表示されます。これには上記のバッジと同じルール（雨 1 mm以上かつ雪以外、雪コード、最低 0°C以下、最高 35°C以上）が適用されます。一つの日が複数の行に表示されることがあります: 例として氷点下の降雪日。
- **パーフェクト**な日とは、穏やかで（最高 15–25°C、乾燥、雪や雷雨なし）、風が弱く（最大風速 25 km/h 未満）、湿度が低く（平均湿度 85% 未満）、夜間も氷点下を上回った日のことです。風速、湿度、または最低気温のデータが欠落している日は、完璧な日としてカウントされません。
- **日次最高気温**は、各日の最高気温を5°Cごとのビンに分けた小さなヒストグラムで、選択した気温単位でラベル付けされます。範囲は下限を含み、上限を含みません（例：0–<5°C または 32–<41°F）。

これらは最寄りのグリッドセルのモデル値であり、公式の平年値や岩場での実測値ではありません。

## 天気とパフォーマンス

**20日以上**の屋外の場所・日付に天気がキャッシュされると、**天気とパフォーマンス**詳細ビューで、異なる天候下での屋外クライミングの状況を比較できるようになります。それまでは、対象となる場所・日付が現在いくつキャッシュされているかが表示されます。ダッシュボードのサマリーは、天気がキャッシュされていない間は非表示のままで、**設定 → ダッシュボード**から移動または非表示にできます。詳細ページには引き続きアクセス可能で、空の状態についての説明が表示されます。

**カウント対象：** 場所・日付の天気がキャッシュされている屋外の完登とアテンプト（他の場所と同じ記録分類）。ジムのルート、完登でもアテンプトでもない記録、および天気の場所がない登攀は除外されます。近似的な周辺の場所やエリアのポリゴンから天気を取得した登攀も含まれ、ビューにはその件数が表示されます。

コンパクトなダッシュボードサマリーには、最高気温/完登率が表示されます。傾向が見られない場合のフォールバックおよび詳細ページでは、以下の両方のコントロールが提供されます。

**グループ化：**

- **日次最高気温：** 10°未満、10–17°、18–24°、25–29°、30°以上。各バンドは下限を含み、ログブックの気温範囲と同様に、次のバンドの直前までとなります。
- **コンディション：** 穏やか、乾燥（測定降水量が 1 mm 未満で雪がないこと。降雨データ欠落は乾燥ではなく不明扱い）、雨、雪、暑い、氷点下、凪（最大風速 25 km/h 未満）、強風（50 km/h 以上）。これらには上記のバッジおよびログブックのルールが適用されます。一日は複数のコンディションに該当する場合があります。風速が25 km/h以上50 km/h未満の場合は、「凪」でも「強風」でもありません。

**指標：**

- **完登率：** 完登とアテンプトの合計に対する完登の割合。
- **限界に近い：** 過去 365 日以内の**同じスタイルとグレード体系**での屋外の最高完登グレードから 2 グレード以内（Vスケールでは 1 Vグレード以内）のグレード付き完登の割合。トラッドはトラッド、スポーツはスポーツと比較され、Vスケールとルートグレードが混ざることはありません。通算の最高ではなく最近のベストを使用することで、年月の経過とともに強くなっても、最近の天気が実際より良く見えることを防ぎます。その年のそれ以前に同じスタイルの完登がない場合や、グレードのない完登は、この指標から除外されます。
- **オンサイト/フラッシュ：** 完登に対するオンサイトとフラッシュの割合。

**正確な読み取り方**

- 各棒グラフはそのバンドの率を示し、線は全体の率を示します。バンドに率を表示するには、少なくとも**3**日間にわたる合計**10**回以上の登攀（その指標の分母）が必要です。それに満たないバンドには「データ不足」と表示されます。
- バンドが**高い**または**低い**とマークされるのは、それ&#x304C;_&#x4ED6;&#x306E;_&#x3059;べての天気の日と比べて、日々の変動では説明できないほど異なっている場合のみです（約95%の信頼区間での両側検定。各側に少なくとも5日必要）。同日の登攀は同じ天気を共有し、通常は同じ岩場やパートナーであるため、テストでは各登攀ではなく各「場所・日」を一つの単位として扱います。一回きりの大きな成果がそれだけでパターンを作ることはありません。
- 一行のサマリーには、選択した指標で最も際立っている区分が表示されるか、まだ際立ったものがないことが示されます。
- これは**相関関係であり、原因ではありません**。季節、岩場、パートナー、およびプロジェクトの進捗状況はすべて、天気とともに変化します。バンドや指標が多いため、たまに「高い」や「低い」が偶然表示されることがあります。

各日次最高気温バンド、および穏やか、雨、雪、暑い、氷点下、凪、強風のコンディションは、それらの登攀にフィルタリングされたログブックにリンクされています。「乾燥」にはログブックのフィルタがありません。詳細ページのグラフの下にある数値テーブルには、すべての区分と三つの指標すべてのカウントがリストされています。カードを表示するだけで天気をリクエストすることはありません。また、プライベートメモが使用されることもありません。

ダッシュボードの最高気温/完登率の比較に明確な傾向がない場合でも、天気とパフォーマンスのカードは、詳細なバンド、ローカルなグループ化/指標コントロール、および数値テーブルを保持します。これらのコントロールはダッシュボードのURLを変更しません。明確な傾向がある場合はコンパクトなサマリーが保持されます。どちらのバージョンからも天気ページへのリンクがあります。最小サンプルの閾値は変更されません。

## ログブックのフィルタとチップ

「限界に近い」のリファレンスは、[岩質とパフォーマンス](/docs/rock-types)と同じスタイルとグレード体系の計算を使用します、可能な場合は登攀したピッチのグレードを使用。天気のリファレンスには、天気がキャッシュされていない屋外の完登が含まれ、365日前の日も含まれますが、比較対象の当日の完登は除外されます。

天気がキャッシュされると、ログブックに**その日の天気**フィルタ（`?weather=`）が追加されます：`fair`、`perfect`、`heat`、`freeze`、`rain`、`snow`、`wind`、または `calm`。**強風の日**は、日次最大10m風速**50 km/h以上**に一致します。これは**Blown Away**と同じ閾値です。**凪/無風の日**は、測定された最大風速が**25 km/h未満**に一致します。これは**完璧な日**で使用される凪の閾値ですが、気温、乾燥、低湿度の条件は必要ありません。風速のデータが欠落している場合はどちらのオプションにも一致しません。25 km/h以上50 km/h未満の日は、どちらの風速フィルタにも一致しません。その他のオプションは、バッジと同じルールを使用します。座標があり、かつその場所のキャッシュされた日付がある**屋外**の登攀のみが一致します。ジムのルート、座標のない登攀、および取得されていない日付は決して一致しません。

キャッシュされた日の行には、小さなテキストチップも表示されます（例：「暑い 36°C」、「氷点下 -2°C」、「雨 4 mm」、「雪」、「強風 55 km/h」、「穏やか 21°C」）。普通の日には何も表示されません。

ログインしている所有者には、**天気が未キャッシュ**（`?missing=weather`）という項目も表示されます。これには、座標と過去の日付があるにもかかわらず、天気がまだキャッシュされていない屋外の登攀がリストされるため、次回のインポートで何が取得されるかを確認できます。閲覧者にはこのオプションは表示されません。

天気が不足しているバックログからは、プロバイダーがすでに確認したが提供できなかった日は除外されます。これらのネガティブキャッシュのエントリは、天気チップを生成せず、自動的に再びキューに入れられることもありません。無効なカレンダー上の日付は、インポーターとバックログの両方から除外されます。

## 最近のアクティビティ

ダッシュボードの**最近のアクティビティ**カードでも、屋外の登攀の日付がキャッシュされている場合、その下に同じテキストチップが表示されます。これらは「その日の天気」というラベルの付いた短いリストとして読み上げられ、色だけで示されることはありません。また、ジムのルート、未キャッシュの日、および普通の天気の場合は省略されます。

## クライミングストーリー

ストーリーのパーセンテージは、天気がまだ不明な日ではなく、キャッシュされた屋外の場所・日付を対象とします。

キャッシュが屋外登攀日の 20 日以上かつ半分以上をカバーしている場合、[クライミングストーリー](/docs/climbing-story)に、あなたが登攀した条件（雪、寒さ、暑さ、雨、または気温差など）についての短い一行を追加できます。これは実際にどのような環境で登攀しているかを説明するものであり、避けている環境については説明しません。カバレッジが低い場合はストーリーに含まれません。

## 登攀カレンダー

[登攀カレンダー](/docs/ascent-calendar)には、**天気**カラーモードがあります（天気がキャッシュされた後にのみ表示されます）。バッジのルールと共通です。色の意味についてはそのページを参照してください。

## セクター：訪問時の気候

**セクター**ページでは、少なくとも **5** 日分のキャッシュされた屋外訪問日がある岩場に、一行のサマリーが表示されます。平均の日次最高・最低気温、およびそれらの日のうち雨、雪、氷点下、または暑い日の割合が表示されます（雪、氷点下、暑い日は 0% を超える場合のみ）。これは実際にそこで登攀した日について説明しているため、あなたが訪問した季節に偏った内容になります。これは公式の平年値や予報では**ありません**。閾値に満たない岩場、ジムのルート、および天気がキャッシュされていない場合は非表示になります。

## 穏やかな天気の割合

屋外の日付が**20日以上**キャッシュされると、天気のコンディションカードに**穏やかな天気の割合**が追加されます。これは、それらの日のう&#x3061;_&#x7A4F;やか_（最高 15-25°C、乾燥、雪や雷雨なし。**Bluebird**と同じルール）だった日の割合です。また、_厳し&#x3044;_&#x65E5;（暑い、氷点下、雨、雪、または強風）の割合も報告されます。乾燥した29°Cの日など、その中間の日はどちらのグループにもカウントされません。

ラベルはグレードではなく、状況を説明するものです。穏やかが60%以上なら「**穏やかな天気を好む**」、厳しい日が50%以上なら「**全天候型クライマー**」、それ以外は「**どちらも楽しむ**」となります。グループは重複することがあります。穏やかで乾燥した日でも、強風だったり夜間に氷点下になったりすることがあります。両方のラベルの閾値を満たす場合は、「**全天候型クライマー**」が優先されます。 20日未満の場合は何も表示されないため、キャッシュが少ない状態でラベル付けされることはありません。リンクをクリックすると、穏やかな日にフィルタリングされたログブックが開きます。ルートのメタデータに基づいた季節の推奨については[ベストな月](/docs/best-months)を参照してください。それらの推奨事項は、ログ記録された訪問からサンプリングされた天気とは別のものです。

穏やかな天気のラベルには判定のために正確な日数が使用されます。表示される割合は小数点第一位に丸められます。表示上の丸めだけでラベルが変わることはありません。

### 天気の詳細からログブックへ

**天気のコンディション**詳細ビューの各コンディション行と日次最高気温の各棒グラフをクリックすると、それらの日にフィルタリングされたログブックが開きます。気温の棒グラフは下限を含み、次の棒グラフの直前までとなります（例：20–24°は20.0 °Cから、25 °Cを含まない直前までをカバーします）。範囲指定は、ソート、ページ送り、または他のフィルタの追加中も適用されたままになります。その範囲のみを削除するには、**天気の範囲をクリア**を使用してください。

カードは各場所での屋外&#x306E;_&#x65E5;&#x6570;_&#x3092;カウントしますが、ログブックには一致するすべて&#x306E;_&#x767B;&#x6500;_&#x304C;リストされるため、二つの数値が異なる場合があります。ワイドスクリーンでは、ログブックにキャッシュされた日次最高、最低、降水量の「天気」列が表示されます。小型スクリーンでは、ルートの横にコンディションチップが表示されます。インドアや未キャッシュの登攀にはダッシュが表示されます。これらのページを表示しても、天気をリクエストすることはありません。

## ルートの座標がない場合の天気の場所

CSVエクスポートには座標が含まれません。天気のインポートとルートデータのインポートの両方が有効（`WEATHER_IMPORT=true` かつ `ROUTE_DATA_IMPORT=true`）な場合、設定されたサポーターAPIキーを使用して、キャッシュされたルートデータにある岩場/セクターIDの場所を検索することもできます。これによって、そのキー所有者のログブックやプロフィールがインポートされることはありません。キー付きのログブックの祖先要素と、ルートAPIの祖先配列の両方がサポートされています。

エリア検索は、ルートインポートの十リクエストの予算と一秒の間隔を共有します。ルート確認に予算が優先的に使われ、残りのリクエストでそれぞれ最大十のエリアを確認します。設定画面には**保留中の天気のエリア**が表示され、すべてのルートの確認が終わると**今すぐ天気の場所を確認**が表示されます。既存のCSVインストールでは、**すべてのルートをリフレッシュ**しなくても、不足しているエリアの場所を埋めることができます。次のインポート実行時にバックログも確認されます。場所の確認が終わると、対象となる日がある場合にバックグラウンドでの天気バッチが開始されます。

エリアのレスポンス（場所が見つからない場合を含む）は、プロバイダーのエリアIDごとに一度キャッシュされます。 `ROUTE_DATA_REFRESH_DAYS` がそれらのオプションの更新期限も制御し、**すべてのルートをリフレッシュ**するとエリア検索が再び可能になります。アクセス失敗時はインポートが停止し、既存のバックオフが適用されます。ルート履歴を読み取れるキーであっても、エリアの場所にアクセスできるとは限りません。 APIがサポート対象の場所を提供しない場合は、以下の明示的な周辺の場所のフォールバックを使用してください。天気ページを表示している間はAPI呼び出しは行われません。

天気は、ルートの明示的な地点、次に最上位の岩場（TLC）の地点、次にキャッシュされたプロバイダーデータからの直近のセクターの地点を優先します。国のみのデータや任意の祖先ジオメトリは無視されます。オリジナルのプロバイダーのジオメトリがない古いキャッシュ地点も引き続き使用可能で、「キャッシュされた地点」としてラベル付けされます。その地点だけから元の精度を復元することはできません。インドアのルートは引き続き除外されます。

設定 → 天気のインポート → **天気の場所を確認**には、屋外エリアと未解決のルート数がリストされます。場所が見つからない場合は、近隣の町を名前/地域と 二文字の国コードで検索し、正しい結果を明示的に選択してください。検索では、入力されたテキストと国コードのみが[Open-Meteo ジオコーディング](https://open-meteo.com/en/docs/geocoding-api)に送信されます。その場所データはGeoNamesから提供されています。ルート、登攀日、プライベートメモ、またはAPIキーを送信することはありません。検索はフォームの送信後にのみ行われ、30日間キャッシュされ、間隔が調整され、エラー時はバックオフされます。

選択された町は**近似的な周辺場所のフォールバック**となり、同じプロバイダーエリアID（エリアIDがない場合はルートのID）でのみ共有されます。ルートの座標を上書きしたり、ルートマップを変更したり、それが最寄りの集落であると主張したりすることはありません。有効なルート/セクター/岩場の地点が常に優先されます。距離、標高、地形の影響で、町の天気は崖の天気とは異なる場合があるため、町ベースのデータは天気の表示やフィルタには表示されますが、**天気のバッジをアンロックすることはできません**。フォールバックはいつでも削除できます。

ログブックと最近のアクティビティには、天気の場所のソースが表示されます。インポーター、バックログ、カレンダー、コンディションカード、岩場訪問サマリー、およびログブックは、同じ解決された場所・日付のキーを使用します。フォールバックを変更または削除すると、古いキーの使用が即座に停止されます。古い天気データはキャッシュに残るため、その場所にある他の登攀で引き続き使用できます。新しく選択した場所を埋めるには、次の天気バッチを取得してください。「ワイプ」は、解決済みの内容、選択された場所、検索結果を消去し、実行中の検索をキャンセルします。

それらの地点がない場合、特定された岩場またはセクターに明示的に入力された GeoJSON Polygon/MultiPolygon ジオメトリがあれば、その最初の外郭境界の座標を直接使用できます。中心点や重心の計算は行われません。これは**概算エリアポリゴン**とラベル付けされており、天気や Summer Sun Face バッジのロックを解除するものではありません。ルートとクラッグの地点が常に優先されます。国・地域の境界、不適切な形状、広大なエリア（保守的に見て対角線 15 km 以上）、および日付変更線を越える形状は除外されます。型指定のない境界配列やドキュメント化されていない Fence フォーマットは引き続きサポートされていません。取得済みのプロバイダーのポリゴンフィクスチャはまだ利用できません。これらのジオメトリのフォールバックも失敗した場合にのみ、選択された町が使用されます。不足している日のデータを取得するには、引き続き気象データのインポートを有効にしておく必要があります。 Summer Sun Face は別途検証されたルートタグの根拠を使用します。[バッジ](/docs/badges)を参照してください。
